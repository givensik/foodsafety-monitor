# 식품안전나라(식약처) 홈페이지 작동 원리 & OpenAPI 실데이터 검증 가이드

식품안전나라(`foodsafetykorea.go.kr`)가 데이터를 수집·노출하는 내부 메커니즘과, **홈페이지 내부 API(`searchBsnList.do` / `bsnInfoDetail.do`)** 및 **식약처 공식 OpenAPI(`I2500` 등)** 의 번호 채번 체계·정렬 조건·배치 반영 시각을 **100% 실제 API 호출 및 원문 응답 대조를 통해 검증한 기술 문서**입니다.

---

## 1. `[확인된 팩트]` 식약처 두 가지 핵심 식별번호 생성 규칙

식약처에는 **① 11자리 `인허가번호(LCNS_NO)`** 와 **② 16자리 `인허가대장번호(BSN_LCNS_LEDG_NO)`** 두 가지 번호가 존재하며, 서로 채번(번호 부여) 주체와 규칙이 다릅니다.

### 1-1. `LCNS_NO` (11자리 인허가번호): `연도(4자리)` + `지자체·기관별 고유 대역 및 일련번호(7자리)`

`searchBsnList.do`에서 수집한 실제 데이터를 지자체(`INSTT_CD`)별로 분류하여 확인한 결과, **뒤 7자리는 각 시·군·구청마다 할당된 고유 숫자 대역 안에서 업종 구분 없이 허가 순번대로 정확히 `+1`씩 증가**합니다.

| 관할 지자체 (`INSTT_CD_NM`) | 기관코드 (`INSTT_CD`) | 실제 인허가번호 (`LCNS_NO`) 연속 채번 내역 | 구조 분석 (`연도 4자리` + `지자체별 대역·일련번호 7자리`) |
| :--- | :---: | :--- | :--- |
| **서울특별시 종로구** | `3000000` | `20260040717` (일반음식점) | `2026` + `0040717` (종로구 `004xxxx` 대역) |
| **서울특별시 용산구** | `3020000` | `20260051011` → `20260051012` → `20260051013` | `2026` + `0051011~0051013` (용산구 `0051xxx` 대역에서 **+1씩 증가**) |
| **서울특별시 성북구** | `3070000` | `20260072983` → `20260072984` → `20260072985` | `2026` + `0072983~0072985` (성북구 `0072xxx` 대역에서 **+1씩 증가**) |
| **서울특별시 강북구** | `3080000` | `20260076722` → `20260076723` → **`20260076724`** | `2026` + `0076722~0076724` (강북구 `0076xxx` 대역에서 **+1씩 증가**) |
| **서울특별시 마포구** | `3130000` | `20260098780` → `20260098781` | `2026` + `0098780~0098781` (마포구 `0098xxx` 대역에서 **+1씩 증가**) |
| **서울특별시 강서구** | `3150000` | `20260109488` → `20260109489` → `20260109490` → **`20260109491`** | `2026` + `0109488~0109491` (강서구 `0109xxx` 대역에서 **업종 불문 +1씩 증가**) |
| **서울특별시 강남구** | `3220000` | `20260147385` → **`20260147386`** | `2026` + `0147385~0147386` (강남구 `0147xxx` 대역에서 **+1씩 증가**) |
| **서울특별시 강동구** | `3240000` | `20260162749` → `20260162750` | `2026` + `0162749~0162750` (강동구 `0162xxx` 대역에서 **+1씩 증가**) |

### 1-2. `BSN_LCNS_LEDG_NO` (16자리 인허가대장번호): `연도(4자리)` + `001(3자리)` + `전국 통합 일련번호(9자리)`

- 홈페이지에서 업체를 클릭할 때 호출되는 상세 팝업(`GET /potalPopup/fooddanger/bsnInfoDetail.do?bsnLcnsLedgNo={16자리}&callPage={토큰}`)은 이 16자리 대장번호를 Primary Key로 사용합니다.
- 지자체별로 대역이 나뉘는 11자리 `LCNS_NO`와 달리, 16자리 `BSN_LCNS_LEDG_NO`는 **전국 지자체에서 식약처 통합 DB로 인허가 원장이 들어오는 순서대로 `+1`씩 매겨지는 전국 통합 시퀀스 번호**입니다.
- **미생성 번호(`+1`) 호출 시 실제 응답**:
  - 아직 생성되지 않은 대장번호를 호출하면 아래와 같이 자바스크립트 에러 팝업 HTML(318바이트)이 반환됩니다.
  ```html
  <!doctype html><html><head><script type="text/javascript">alert('시스템에러가 발생하였습니다. 관리자에게 문의하십시오.'); history.back();</script></head><body></body></html>
  ```

## 2. `[확인된 팩트]` 홈페이지 ‘업소검색’(`searchInfoCompany.do`) 통신 원리 및 `s_order_by` 검증

### 2-1. 3단계 통신 구조

| 단계 | 호출 엔드포인트 | 역할 및 실측 확인된 동작 |
| :--- | :--- | :--- |
| **Step 1.<br/>보안 토큰 발급** | `GET /portal/specialinfo/searchInfoCompany.do` | • 접속 시 서버가 세션 쿠키를 발급하고 HTML 본문 내 `<input type="hidden" id="callPage" value="...">` 토큰을 내려줍니다. |
| **Step 2.<br/>목록 AJAX 조회** | `POST /ajax/portal/specialinfo/searchBsnList.do?callPage={토큰}` | • URL 쿼리의 `callPage`와 `Cookie` 헤더의 `callPage`가 일치해야 정상 JSON(`bsnList`)이 반환됩니다.<br/>• 총 건수는 `POST /ajax/portal/specialinfo/searchBsnListCnt.do`(`totCnt`)에서 별도로 조회합니다. |
| **Step 3.<br/>상세 팝업 조회** | `GET /potalPopup/fooddanger/bsnInfoDetail.do?bsnLcnsLedgNo={대장번호}&callPage={토큰}` | • 파라미터 `bsnLcnsLedgNo`와 함께 URL 쿼리 및 `Cookie` 헤더에 동일한 `callPage` 토큰을 전달해야 정상 HTML 테이블(`<th>업체명</th><td>...</td>`)이 반환됩니다. |

### 2-2. `s_order_by` 정렬 파라미터 화이트리스트 실측 검증 결과

웹 페이지 UI의 `<select id="s_order_by">`에는 두 가지 옵션만 존재합니다:
```html
<option value="bssh_nm">업소명순</option>
<option value="reg_dt">최신등록순</option>
```

소문자 `"reg_dt"`, 대문자 `"REG_DT"`, 그리고 UI 옵션에 없는 실제 응답 컬럼명 5개(`lcns_no`, `bsn_lcns_ledg_no`, `prsdnt_nm`, `site_addr`, `prms_dt`)를 직접 주입하여 `searchBsnList.do` 응답을 비교한 실측 결과입니다:

```text
s_order_by=reg_dt             -> Top 3: ['20260051013 (21시아이스 용산아이파크몰)', '20260123112 (동동국밥 문래점)', '20260109489 (도미노피자 방화점)']
s_order_by=REG_DT             -> Top 3: ['20100050301 ((주)그린버그)', '20100050031 ((주)바이오폴리메드)', '20100107739 ((주)와세다야에프엔비)']
s_order_by=bssh_nm            -> Top 3: ['20100050301 ((주)그린버그)', '20100050031 ((주)바이오폴리메드)', '20100107739 ((주)와세다야에프엔비)']
s_order_by=lcns_no            -> Top 3: ['20100050301 ((주)그린버그)', '20100050031 ((주)바이오폴리메드)', '20100107739 ((주)와세다야에프엔비)']
s_order_by=bsn_lcns_ledg_no   -> Top 3: ['20100050301 ((주)그린버그)', '20100050031 ((주)바이오폴리메드)', '20100107739 ((주)와세다야에프엔비)']
s_order_by=prsdnt_nm          -> Top 3: ['20100050301 ((주)그린버그)', '20100050031 ((주)바이오폴리메드)', '20100107739 ((주)와세다야에프엔비)']
s_order_by=site_addr          -> Top 3: ['20100050301 ((주)그린버그)', '20100050031 ((주)바이오폴리메드)', '20100107739 ((주)와세다야에프엔비)']
s_order_by=prms_dt            -> Top 3: ['20100050301 ((주)그린버그)', '20100050031 ((주)바이오폴리메드)', '20100107739 ((주)와세다야에프엔비)']
```
- **결론**: `s_order_by`는 입력값을 SQL에 직접 넣지 않고, 서버에서 정확히 소문자 `"reg_dt"`와 일치할 때만 최신순으로 정렬하며, 그 외의 모든 값(대문자 `"REG_DT"` 및 다른 실제 컬럼명 포함)은 기본 정렬(`bssh_nm`, 업소명 가나다순)로 처리됩니다.

### 3-2. 신규 채번 시 가등록(상호명·소재지 공란 `""`) 선행 노출 현상

20:01 KST에 서울 최신 목록 최상단에 새로 올라온 4건(`2026001000413407` ~ `2026001000413410`)을 `searchBsnList.do`, `bsnInfoDetail.do`, 그리고 OpenAPI `I2500` 세 곳에서 동시에 조회한 실데이터입니다:

| 대장번호 (`BSN_LCNS_LEDG_NO`) | 인허가번호 (`LCNS_NO`) | 관할 지자체 | 업종 | 대표자 | 허가일 (`PRMS_DT`) | 상호명 (`BSSH_NM`) | 소재지 (`SITE_ADDR`) |
| :--- | :--- | :--- | :--- | :---: | :---: | :---: | :---: |
| `2026001000413407` | `20260147386` | 서울특별시 강남구 | 유통전문판매업 | `소*범` | `20261016` | `""` (공란) | `""` (공란) |
| `2026001000413408` | `20260109491` | 서울특별시 강서구 | 즉석판매제조가공업 | `장*철` | `20261016` | `""` (공란) | `""` (공란) |
| `2026001000413409` | `20260076724` | 서울특별시 강북구 | 일반음식점 | `최*성` | `20261016` | `""` (공란) | `""` (공란) |
| `2026001000413410` | `20260040717` | 서울특별시 종로구 | 일반음식점 | `*` | `20261016` | `""` (공란) | `""` (공란) |

- 이 레코드들은 인허가번호(기존 구청 마지막 번호 `+1`), 대장번호, 업종, 대표자, 허가일자(`PRMS_DT`)는 정식 등록되어 있으나, 초기 동기화 시점에 상호명(`BSSH_NM`)과 소재지(`SITE_ADDR`)가 빈 문자열(`""`)로 먼저 적재된 상태입니다.
- 대시보드(`store.givensik.space`)에서는 이를 **`신규 채번 (상호·주소 반영 대기중)`** 배지로 구분해 표시하며, 이후 식약처 DB에 상호명이 채워지면 자동으로 실제 상호명으로 갱신합니다.

### 3-3. `[아직 직접 확인/검증하지 않은 영역]`
- **오전(00:00 ~ 13:20) 및 심야 시간대 추가 배치 유무**: 당일 13:21부터 실측을 시작했으므로, 자정~오전 시간대에 또 다른 정기 동기화가 수행되는지 여부는 추가 시간대 실측이 필요합니다.
- **가등록(공란) 레코드의 상호명 채워짐 소요 시간**: `413407`~`413410` 레코드의 상호명과 주소가 다음 날 배치에서 채워지는지, 혹은 수 시간 내 후속 배치에서 채워지는지는 지속 폴링을 통해 검증할 수 있습니다.

## 4. 홈페이지 내부 API vs OpenAPI (`I2500` 등) 제공 항목 비교

| 정보 항목 | 홈페이지 목록 API (`searchBsnList.do`) | 홈페이지 상세 팝업 (`bsnInfoDetail.do`) | 공식 OpenAPI (`I2500` 등) | 비고 및 활용법 |
| :--- | :---: | :---: | :---: | :--- |
| **인허가번호 (11자리)** | O (`LCNS_NO`) | O | O (`LCNS_NO`) | 지자체별 대역 + 일련번호 (`+1`씩 증가) |
| **인허가대장번호 (16자리)** | O (`BSN_LCNS_LEDG_NO`) | O (요청 파라미터) | X | 전국 통합 일련번호 (`bsn_lcns_ledg_no`로 조회) |
| **상호명 (업소명)** | △ (`BSSH_NM`, 일부 `"NULL"` 또는 가등록 `""`) | O (`<th>업체명</th>`) | O (`BSSH_NM`) | 목록에서 `"NULL"`일 때 상세 팝업으로 복원 |
| **업종명** | O (`INDUTY_CD_NM`) | O | O (`INDUTY_CD_NM`) | 예: 일반음식점, 휴게음식점, 축산물가공업 |
| **대표자명** | O (`PRSDNT_NM`) | X | △ (`PRSDNT_NM`, 공란 다수) | 목록 API에는 마스킹(`김*형`) 형태로 제공 |
| **소재지 도로명주소** | O (`SITE_ADDR`) | O | O (`ADDR`) | 상세 번지 및 건물명 포함 |
| **관할 지자체명** | O (`INSTT_CD_NM`) | X | X (주소에서 추출) | 예: `서울특별시 용산구`, `경기도 파주시` |
| **실제 인허가일자** | **X (미노출)** | **X (미노출)** | **O (`PRMS_DT`)** | **`YYYYMMDD` 형식 (예: `20261016`, `20261017`)** |
| **최종수정일 검색** | X (`s_order_by=reg_dt` 정렬만 지원) | X | **O (`CHNG_DT=YYYYMMDD`)** | 당일 날짜는 19:00 이후 `INFO-000` 개방 |
