# 식품안전나라(식약처) 홈페이지 작동 원리 & OpenAPI 데이터 명세 총정리

식품안전나라(`foodsafetykorea.go.kr`)가 데이터를 수집·노출하는 내부 메커니즘과, **홈페이지 내부 API** 및 **식약처 공식 OpenAPI** 각각의 구조·차이점·수집 가능 항목을 정리한 기술 문서입니다.

---

## 1. 식약처(식품안전나라) 홈페이지는 어떤 원리로 돌아가는가?

### 1-1. 데이터의 탄생과 이동 경로 (지자체 → 식약처 DB)
1. **지자체 새올행정시스템 인허가 결재**:
   - 음식점·식품업체 영업신고/허가는 식약처에 직접 하는 것이 아니라 **관할 시·군·구청 위생과**에서 담당 공무원이 평일 일과시간(09:00~18:00)에 결재합니다.
   - 따라서 **주말(토·일)·공휴일에는 신규 인허가 원천 데이터가 발생하지 않으며**, 금요일 업무 마감분이 주말 내내 최신 목록 상단에 머무르게 됩니다.
2. **식약처 통합 DB의 2가지 핵심 식별번호**:
   - **`LCNS_NO` (인허가번호, 11자리)**: `허가연도(4자리) + 지자체·일련번호(7자리)` 형태(예: `20260051013`). 외부에 공개되는 공식 영업허가번호입니다.
   - **`BSN_LCNS_LEDG_NO` (인허가대장번호, 12~16자리)**: 식약처 내부 DB의 고유 Primary Key(예: `202603039237`). 홈페이지 상세 팝업을 열 때 사용됩니다.

### 1-2. 홈페이지 ‘업소검색’(`searchInfoCompany.do`)의 3단계 통신 원리

| 단계 | 호출 엔드포인트 | 역할 및 내부 동작 원리 |
| :--- | :--- | :--- |
| **Step 1.<br/>보안 토큰 발급** | `GET /portal/specialinfo/searchInfoCompany.do` | • 접속 시 서버가 `JSESSIONID` 쿠키를 굽고, HTML 본문 안에 `<input type="hidden" id="callPage" value="...난수토큰...">` 값을 심어줍니다.<br/>• 접속자가 몰릴 때는 앞단에서 **NetFUNnel(`wait.foodsafetykorea.go.kr`)** 대기열 시스템이 작동합니다. |
| **Step 2.<br/>목록 AJAX 조회** | `POST /ajax/portal/specialinfo/searchBsnList.do?callPage={토큰}` | • **토큰 대조 보안**: 요청의 URL 파라미터 `callPage`와 `Cookie` 헤더 안의 `callPage` 값이 일치하지 않으면 **0바이트(빈 문자열/널 바이트 `\u0000`)** 를 반환하여 크롤링을 차단합니다.<br/>• **정렬(`s_order_by=reg_dt`)**: 내부 Oracle SQL에서 `ORDER BY REG_DT DESC`(DB 등록일 최신순)로 정렬해 가장 최근 등록된 업소부터 내려줍니다.<br/>• **필드 숨김**: 정렬에는 `REG_DT`를 쓰면서도, 정작 JSON 응답(`bsnList`)에는 **`PRMS_DT`(허가일)와 `TELNO`(전화번호)를 빼고** 내려보냅니다.<br/>• **`"NULL"` 상호명 버그**: 위탁급식영업·집단급식소 등 일부 업종은 목록 SQL 테이블 조인(JOIN) 누락으로 인해 상호명(`BSSH_NM`)이 `"NULL"` 문자열로 반환됩니다. |
| **Step 3.<br/>상세 팝업 조회** | `GET /potalPopup/fooddanger/bsnInfoDetail.do?bsnLcnsLedgNo={대장번호}&callPage={토큰}` | • 목록에서 특정 업체를 클릭할 때 열리는 서버사이드 렌더링(JSP) 팝업입니다.<br/>• Step 2에서 상호명이 `"NULL"`로 나왔던 업체도 이 상세 페이지의 `업체명 : <span>...</span>` 영역에는 실제 상호명이 정상 출력됩니다. |

## 2. 식약처 OpenAPI는 어떻게 구성되어 있는가?

식약처는 홈페이지와 별개로 데이터 개방을 위한 전용 서버(`http://openapi.foodsafetykorea.go.kr`)를 운영합니다.

### 2-1. 독특한 URL Path 파라미터 구조
일반적인 `?key=val` Query String 대신 **슬래시(`/`) 경로 뒤에 조건들을 이어 붙이는 구조**입니다.

```text
http://openapi.foodsafetykorea.go.kr/api/{keyId}/{serviceId}/{dataType}/{startIdx}/{endIdx}/{조건1=값1}/{조건2=값2}
```

- **`keyId` (인증키)**:
  - **`sample`**: 회원가입 없이 바로 호출할 수 있는 테스트 키입니다. **1회 최대 5건(`1/5`)** 까지만 조회 가능하며, 동일 IP에서 연속 ~20회 이상 호출 시 **`INFO-310` ("샘플키로 더 이상 호출할 수 없습니다")** 제한이 걸립니다.
  - **정식 인증키**: 식약처 사이트 회원가입 후 무료로 즉시 자동 발급되며, **1회 최대 1,000건(`1/1000`)** 까지 대량 조회 가능합니다.
- **OpenAPI의 `19시` 배치 규칙 (`INFO-700`)**:
  - `CHNG_DT`(최종수정일자) 조건으로 오늘 날짜 데이터를 요청하면, 당일 저녁 7시 이전에는 `"INFO-700: 오늘날짜에 생성 및 변경된 데이터는 19시 이후에 호출이 가능합니다."` 라는 응답이 반환됩니다.

## 3. 각 API를 통해 어떤 정보를 가져올 수 있는가?

### 3-1. 홈페이지 내부 API vs OpenAPI (`I2500`) 제공 항목 비교

| 정보 항목 | 홈페이지 목록 API (`searchBsnList.do`) | 홈페이지 상세 팝업 (`bsnInfoDetail.do`) | 공식 OpenAPI (`I2500` 등) | 비고 및 활용법 |
| :--- | :---: | :---: | :---: | :--- |
| **인허가번호** | O (`LCNS_NO`) | O | O (`LCNS_NO`) | 두 API를 연결하는 핵심 Key (11자리) |
| **인허가대장번호** | O (`BSN_LCNS_LEDG_NO`) | O (요청 파라미터) | X | 홈페이지 상세 팝업 호출용 내부 PK |
| **상호명 (업소명)** | △ (`BSSH_NM`, 일부 업종 `"NULL"`) | O (전 업종 정상 표기) | O (`BSSH_NM`) | 목록 API에서 `"NULL"`일 때 상세 팝업으로 복원 |
| **업종명** | O (`INDUTY_CD_NM`) | O | O (`INDUTY_CD_NM`) | 예: 일반음식점, 휴게음식점, 유통전문판매업 |
| **대표자명** | O (`PRSDNT_NM`) | O | O (`PRSDNT_NM`) | 개인정보 정책에 따라 일부 공란 처리됨 |
| **소재지 도로명주소** | O (`SITE_ADDR`) | O | O (`ADDR`) | 상세 번지 및 건물명 포함 |
| **관할 지자체명** | O (`INSTT_CD_NM`) | X | X (주소에서 추출) | 예: `서울특별시 용산구`, `경기도 안성시` |
| **영업 상태 (정상/폐업)** | O (`CLSBIZ_DVS_CD_NM`) | O | △ (별도 폐업 API 존재) | 목록 API에서는 `"정상"` 여부 즉시 확인 가능 |
| **실제 인허가일자** | **X (숨김)** | **X (숨김)** | **O (`PRMS_DT`)** | **`YYYYMMDD` 형식 (예: `20261016`)** |
| **업소 전화번호** | **X (숨김)** | **X (숨김)** | **O (`TELNO`)** | 구청 신고 시 전화번호를 기재한 업소는 반환됨 |
| **최종수정일 검색** | X (`s_order_by=reg_dt` 정렬만 지원) | X | **O (`CHNG_DT=YYYYMMDD`)** | 특정 날짜 이후 신규/변경된 업소만 일괄 수집 가능 |
